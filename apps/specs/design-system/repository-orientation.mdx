---
title: "Repository Orientation"
description: "Light orientation for the future Civic Design System repository."
---

The Civic Design System should eventually have its own repository.

The current hub presents doctrine and specs orientation. It should not become
the canonical implementation workspace for the Civic Design System.

In the two-concept model, that repository is the implementation workspace for
a component of the Civic Stack Model.

## Future Repository

Light orientation:

```text
hiaka-civic-design-system/
  specs/
  tokens/
  components/
  figma/
  examples/
  conformance/
```

This orientation is intentionally light. It names the expected responsibilities
without freezing the final repository layout too early.

## Expected Responsibilities

The future repository is expected to contain:

* Civic Design System specs aligned with Civic Stack Specs;
* token definitions;
* UI component reference implementation;
* Figma bridge or design assets;
* examples of product implementation;
* conformance guidance and review checklists.

## What Stays In The Hub

The hub should continue to provide:

* public explanation of Civic Stack Model and Civic Stack Specs;
* landing content for decision makers and builders;
* Mintlify presentation of current specs;
* links to future canonical repositories;
* high-level repository strategy.

The hub's `packages/ui` package remains local hub UI infrastructure.

## Relationship To Specs Portal

Mintlify is a presentation surface for specs. Civic Design System specs are
presented under Civic Stack Specs because Civic Stack Specs specify the
components of the Civic Stack Model.
