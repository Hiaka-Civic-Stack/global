The Civic Stack Model explains what Hiaka is made of.

It defines how public participation services are composed from reusable
concepts instead of one hard-coded application.

## Composition Model

```text
Civic Blueprints
  compose Civic Modules
  and Civic Design System patterns
  with support from Shared Digital Services
```

## Responsibilities

The Civic Stack Model owns:

* Civic Modules;
* Civic Design System;
* Civic Patterns inside the Civic Design System;
* Civic Blueprints;
* Shared Digital Services;
* composition rules;
* architectural boundaries.

The Civic Design System is part of the model. It generalizes the former
standalone Civic Patterns concept into a broader civic experience framework
organized around Intent, Semantic and Pattern layers.

The model does not replace specifications. Those belong to the Civic Stack
Specs.

## Explore The Model

The model has three composable components and one supporting-services boundary:

* [Civic Modules](/model/modules) own reusable civic capabilities and business
  rules.
* [Civic Design System](/model/design-system) defines civic intents, semantic
  language and experience patterns.
* [Civic Blueprints](/model/blueprints) describe complete civic processes by
  composing Modules and Design System patterns.
* [Shared Digital Services](/model/shared-digital-services) provide generic
  infrastructure through explicit ports and adapters.

Read [Composition](/model/composition) for the central composition rule and the
boundaries that keep the model reusable.

## Model And Specs

These pages explain the concepts and their relationships. Civic Stack Specs
define the testable contracts for particular Modules, Design System elements,
Blueprints and shared interfaces.

Use the model to understand what a Hiaka component is. Use the specs to build,
integrate or evaluate one.
