The Civic Design System is an autonomous Hiaka domain for designing civic
technology products.

It is both a civic-tech design framework and an experience standard that
products can use for conformance review. It is not the Hiaka hub UI, Payload,
shadcn or `packages/ui`.

## What It Owns

The Civic Design System owns:

* civic experience principles;
* experience standards;
* civic interaction patterns;
* accessibility and localization expectations;
* experience conformance;
* design-system governance.

It does not own civic domain rules. Those belong to the Civic Stack Model.

It does not own module APIs, domain events, authorization contracts or
interoperability rules. Those belong to Civic Stack Specs.

## Specs Boundary

The word "specs" appears in more than one Hiaka domain.

Design System specs define civic experience standards. Civic Stack Specs define
implementation contracts for the stack.

Both can be presented in this Mintlify portal, but they are different domains.
