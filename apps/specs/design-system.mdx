The Civic Design System is the Civic Stack Model component for designing civic
technology experiences.

It is both a civic-tech design framework and a civic experience standard that
products can use for specification, conformance review and improvement. It is
not the Hiaka hub UI, Payload, shadcn or `packages/ui`.

It generalizes the former standalone Civic Patterns concept. Patterns such as
inform, consult, contribute, deliberate, decide and account now live inside the
Civic Design System.

## Model

The Civic Design System is organized around a Conceptual Model and an
Operational Model.

```text
Civic Design System
├── Conceptual Model
│   ├── Intent Layer
│   ├── Semantic Layer
│   └── Pattern Layer
│
└── Operational Model
    ├── Standards and conformance
    └── Reference implementation artifacts
```

Civic principles are transverse foundations. They govern all layers and
artifacts, but they are not a separate conceptual layer.

## Boundaries

The Civic Design System owns civic experience rules, semantic language,
patterns and conformance criteria.

It does not own module business rules. Those belong to Civic Modules. It does
not own blueprint lifecycle contracts. Those belong to Civic Blueprints.

## Specs Boundary

Civic Design System specs are part of Civic Stack Specs because Civic Stack
Specs specify the components of the Civic Stack Model.
