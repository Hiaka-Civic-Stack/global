## Contribution NFRs

| ID | Requirement | Expected evidence |
| --- | --- | --- |
| `CONT-NFR-001` | Draft updates **MUST** preserve ownership and reject stale versions without losing acknowledged content. | Concurrency and persistence tests |
| `CONT-NFR-002` | Retried submissions **MUST NOT** create duplicate contributions or duplicate publication events. | Idempotency and event-producer tests |
| `CONT-NFR-003` | Moderation reasons **MUST** separate participant-visible information from protected administrative detail. | Privacy and representation tests |
| `CONT-NFR-004` | Public content and attachment metadata **MUST** pass documented validation and safe-rendering contracts. | Malformed-content, media-type and adapter tests |
| `CONT-NFR-005` | Public list and owner-tracking queries **MUST** be paginated and benchmarked against deployment targets. | Repeatable workload report |
| `CONT-NFR-006` | State, moderation and response history **MUST** remain attributable and recoverable under retention policy. | Audit, retention and recovery tests |

## Test Expectations

Evidence includes aggregate tests for every state transition, application tests
for both publication policies, API and event contracts, authorization denial
tests, privacy tests, persistence concurrency tests and adapter failure tests.
