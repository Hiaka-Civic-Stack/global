## Accountability NFRs

| ID | Requirement | Expected evidence |
| --- | --- | --- |
| `ACC-NFR-001` | Significant history entries **MUST** be append-only; corrections supersede rather than overwrite. | Persistence and tamper tests |
| `ACC-NFR-002` | Every evidence reference **MUST** retain source, author, timestamp, media metadata and integrity information when available. | Provenance and adapter tests |
| `ACC-NFR-003` | Numeric progress **MUST** be deterministic for the same declared method and input versions. | Calculation and replay tests |
| `ACC-NFR-004` | Public history **MUST** remain chronological, attributable and available under the configured retention policy. | Ordering, retention and recovery tests |
| `ACC-NFR-005` | Public commitment queries **MUST** be paginated and benchmarked against deployment-defined targets. | Repeatable workload report |
| `ACC-NFR-006` | Provider outages **MUST NOT** erase acknowledged updates and **MUST** expose diagnosable retry or degraded states. | Failure injection and recovery tests |

## Test Expectations

Evidence includes aggregate transition tests, append-only persistence tests,
API and event contracts, authorization denial tests, public representation
tests, deterministic progress tests and source/document adapter failure tests.
