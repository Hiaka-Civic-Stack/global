The Civic Design System is the experience component of the Civic Stack Model.

It answers:

**How should civic actors understand, perform and trust recurring civic
interactions?**

## Conceptual Model

The Civic Design System organizes civic experience through three layers:

* Intent Layer: the civic job an actor needs to accomplish;
* Semantic Layer: the shared language for actors, processes, stages, statuses,
  evidence, decisions, commitments and territories;
* Pattern Layer: reusable interaction patterns that realize intents through the
  semantic language.

Civic Patterns such as Inform, Consult, Contribute, Deliberate, Decide and
Account live inside the Civic Design System.

## Boundaries

The Civic Design System does not own Module business rules or Blueprint
lifecycle contracts. A pattern can identify Module touchpoints, but it cannot
become the source of truth for contribution state, eligibility decisions or
commitment progress.

The Civic Design System is also distinct from the UI implementation of this
hub. Payload, shadcn and `packages/ui` are not the canonical Civic Design
System.

## Relationship To Blueprints

Blueprints use Civic Design System patterns to make Module capabilities
understandable and usable as part of a complete civic process.

## Model Versus Specs

This page defines the Civic Design System's place in the model. Read the [Civic
Design System specs](/design-system) for intent specs, semantic language,
pattern specs, standards, conformance and reference implementation guidance.
